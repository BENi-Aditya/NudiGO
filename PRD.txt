PRD — Kannada Language Learning App MVP

1. Product Definition
Working name: NudiGo
Product type: Gamified language-learning web application
Primary language: Kannada
Initial learner language: English
Platform: Responsive web application
Hackathon scope: 13-hour MVP
Target: A polished, highly interactive demonstration of a Duolingo-like learning experience specifically optimized for people who need practical Kannada in everyday Karnataka situations.
The product should feel like a real consumer application rather than a hackathon prototype.
The core product loop is:
Choose goal → Start lesson → Learn → Practice → Make mistakes → Receive feedback → Review → Complete lesson → Earn progress → Continue learning → Practice conversation
The MVP should demonstrate this loop extremely well.
The application must not attempt to reproduce all of Duolingo. It should reproduce the feeling of learning through short, rewarding, progressively difficult interactions.
The primary differentiator is contextual Indian-language learning.
Instead of teaching Kannada as an abstract collection of vocabulary, the MVP should teach Kannada through situations a person living in Bengaluru/Karnataka actually encounters.
Examples:
Talking to an auto driver
Ordering food
Asking for directions
Buying something
Introducing yourself
Speaking to classmates
Asking someone to repeat themselves
Basic everyday conversation

2. Product Vision
The long-term vision is:
Make India's regional languages approachable, practical, and habit-forming to learn.
Kannada is the first language.
The underlying product concept should eventually support:
Kannada
Tamil
Telugu
Malayalam
Bengali
Assamese
Marathi
Gujarati
Punjabi
Odia
Hindi
and other Indian languages.
However, the MVP must only expose Kannada, and Kannada only.
The architecture and content model should be designed so additional languages can eventually be added without rebuilding the learning engine.

3. Target User
The primary MVP persona is:
A young person, whose 2nd or 3rd language is English, has recently moved to Bengaluru and wants to learn enough Kannada to comfortably handle everyday interactions.
A particularly strong example is:
A college student who has moved to Bengaluru and knows no Kannada whatsoever.
The user is not initially trying to achieve literary fluency.
Their immediate goals are:
"I want to understand people."
"I want to respond without opening Google Translate."
"I want to survive everyday conversations."
This should influence the content.

4. Product Principles
4.1 Learn by doing
Avoid long explanations. The learner should interact with Kannada almost immediately.
4.2 Small learning units
Lessons should feel achievable in approximately 3–5 minutes. The user should frequently think: "I'll just do one more lesson."
4.3 Immediate feedback
Every answer should produce immediate feedback.
Correct: ✓ Correct
Incorrect: ✗ Not quite
Then explain or reveal the correct answer.
4.4 Repetition without boredom
The same vocabulary should appear through different exercise formats.
A learner shouldn't see: ನೀರು = water
once and never encounter it again.
Instead:
ನೀರು → water
water → ನೀರು
hear ನೀರು
use ನೀರು in a sentence
construct a sentence containing ನೀರು
4.5 Context over isolated vocabulary
Prefer "How much is this?" over: "How much"
Prefer "I want water." over "water"
4.6 Visual feedback
The user should always understand:
where they are
what they're learning
how well they're doing
what comes next.
4.7 Delightful interaction
Animations should communicate state. Correct answers should feel satisfying. Wrong answers should feel corrective rather than punishing.
Transitions should feel intentional.

The lesson engine is the most important technical/product component.
A lesson contains:
Lesson
 ├── title
 ├── description
 ├── estimatedDuration
 ├── concepts[]

3–5 minutes.

15. Lesson Header
During the lesson:
Top:
←              4 / 10
━━━━━━━━━━━━━━━━━━
Show progress continuously.
There should be an exit button.
If the user exits, preserve progress locally.

16. Exercise Types
The MVP should implement five exercise types.
Exercise Type 1 — Multiple Choice Translation
Display:
What does this mean?
Large Kannada:
안녕하세요
For Kannada, use actual Kannada:
ನಮಸ್ಕಾರ
Options:
Hello
Goodbye
Thank you
Sorry
User selects.
After selection:
Correct: ✓ Correct!
Incorrect: Not quite.
Show: ನಮಸ್ಕಾರ = Hello
Then: Continue

17. Exercise Type 2 — Select the Kannada Word
Prompt: Select "water"
Options:
ಮನೆ
ನೀರು
ಊಟ
ರಸ್ತೆ
This tests English → Kannada retrieval.

18. Exercise Type 3 — Sentence Construction
Prompt: Build the sentence.
Meaning: I want water.
Word tiles:
ಬೇಕು
ನೀರು
ನನಗೆ
User arranges: ನನಗೆ | ನೀರು | ಬೇಕು
The interface should make dragging/tapping extremely satisfying.
For the MVP, tapping a word can add it to the sentence.
Tapping an already selected word can remove it.

19. Exercise Type 4 — Listening
Show: Listen and choose what you hear.
Audio button: 
🔊
Then options.
The user listens and selects the corresponding meaning.
For the MVP, audio can be pre-generated and stored locally or loaded from a static source.
Do not attempt to build custom speech synthesis.

20. Exercise Type 5 — Translation Input
Prompt: Translate into Kannada.
English: I want water.
Input: ___________________________________
Expected: ನನಗೆ ನೀರು ಬೇಕು.
For the MVP, exact string matching is acceptable.
However, allow minor whitespace differences.
Do not attempt sophisticated natural-language grading unless time permits.

21. Exercise Feedback
Feedback should be immediate.
Correct:
green success state
subtle animation
positive microcopy
correct answer remains visible.
Incorrect:
red/coral error state
correct answer displayed
short explanation if useful.
Do not punish mistakes excessively.
The user should always know: what they answered, whether it was correct, what the correct  answer was, and why, if relevant.

22. Hearts / Lives
Do not implement the traditional Duolingo heart system.
It introduces unnecessary complexity and can interfere with the core demonstration.
Instead, mistakes simply reduce the lesson score.
Example:
8 / 10 correct
The user can continue regardless of mistakes.

23. Lesson Scoring
Every exercise contributes to a score.
Example:
correct = +10
incorrect = +0
At completion: 8 / 10 correct; 80% accuracy
Also track concepts.
Example:
ನೀರು: strong
ಬೇಕು: weak
ನನಗೆ: strong
This information feeds the Review screen.

Survival Kannada

26. Progress System
Maintain a simple local state.
Track:
currentUnit
completedLessons
xp
streak
conceptScores
lastStudyDate
Use localStorage.
SQLite3, or even a JSON-file-based system is enough for the MVP.

27. XP
Keep it extremely simple.
Each completed exercise: +10 XP
Lesson completion: +20 bonus XP
Therefore a 10-question lesson gives approximately: 120 XP
Display XP visually.
Do not create complicated economies.

28. Streak
Implement a simple daily streak.
If the user completes at least one lesson today: streak += 1
If the previous study date was yesterday.
If the user returns after missing a day: streak = 1
For a hackathon demo, this is sufficient.

29. Review System
The Review page should answer: "What am I bad at?"
Show concepts with low scores.
Example:
Review your weak words
ಬೇಕು
need / want
You struggled with this twice.
CTA: Practice
The review session should select approximately 5 weak concepts.
Use a mixture of exercise types.

30. Adaptive Learning
Keep the algorithm simple.
Every concept has: score: 0–5
Correct answer: score = min(score + 1, 5)
Incorrect: score = max(score - 1, 0)
Interpretation:
0–1 = weak
2–3 = learning
4 = strong
5 = mastered
When generating review exercises, prioritize lower-score concepts.
This gives you a legitimate adaptive-learning mechanism without wasting hackathon time.

33. Conversation UI
Make it resemble a messaging interface rather than an AI dashboard.
Top: 🍛 Restaurant
Subtitle: Order something in Kannada.
AI message: ನಮಸ್ಕಾರ! ಏನು ಬೇಕು?
Below: What the AI said
Optional English translation: Hello! What would you like?
The learner responds.
The application sends the response to the AI.
AI evaluates it.

34. AI Feedback
The AI should not simply say: Correct.
It should respond as a language tutor.
Example: Nice! I understood you.
Then: 
A more natural way to say that is: ನನಗೆ ದೋಸೆ ಬೇಕು. "I want dosa."
Then continue the conversation.
This is much more compelling than a generic chatbot.

35. AI Guardrails
The AI should be instructed to:
remain in the selected scenario
use beginner-level Kannada
avoid unnecessarily difficult vocabulary
provide English explanations when necessary
correct major errors
encourage Kannada responses
not overwhelm the learner
progressively increase difficulty.
For beginners, the AI should generally produce: Kannada + English translation
Later: Kannada only

36. Conversation Difficulty
The conversation should start easy.
Example:
AI: ನಮಸ್ಕಾರ! ಏನು ಬೇಕು?
User: ನನಗೆ ದೋಸೆ ಬೇಕು.
AI: ಖಂಡಿತ. ಇನ್ನೇನು ಬೇಕು?
User: ನೀರು ಬೇಕು.
AI: ಸರಿ. ಒಂದು ದೋಸೆ ಮತ್ತು ಒಂದು ನೀರು.
This demonstrates that the learner is actually using the language.

Prioritize phrases.

Greetings

52. What Makes This "Duolingo-like"
The MVP should reproduce these principles:
Micro-lessons : Short sessions.
Progression : Users visibly move through a path.
Immediate feedback : Every interaction has a consequence.
Repetition : Concepts return.
Retrieval : Users have to recall rather than simply recognize.
Gamification : XP, streaks and completion.
Adaptive review : Weak concepts return more frequently.
Increasing difficulty : Scaffolding gradually disappears.
Habit formation : The user always has an obvious next action.

53. What Makes It Different
The core differentiator should be: Context-first regional language learning. The product isn't "Learn 100 Kannada words." It is "Learn how to survive your first week in Bengaluru."
This distinction should be visible throughout the UX.
Instead of units like: “Animals”, “Colors”, “Numbers”, the initial path should emphasize: “Talk to an auto driver.”, “Order food.”, “Ask for directions.”, “Introduce yourself.”, “Tell someone you don't understand Kannada.”

55. MVP Success Criteria
The MVP is successful if a completely new user can:
Understand what the application does within 10 seconds.
Start a Kannada lesson within 30 seconds.
Learn at least 3–5 useful Kannada phrases.
Complete a short interactive lesson.
Receive immediate feedback.
See measurable progress.
Review mistakes.
Enter an actual Kannada conversation.
Understand why the product is specifically useful for someone living in Karnataka.
The application does not need hundreds of lessons to satisfy these criteria.
It needs one excellent learning experience.

57. The One Rule for the Team
If a feature doesn't improve this loop:
Learn → Practice → Feedback → Remember → Use
